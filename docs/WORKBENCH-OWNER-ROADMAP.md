# Brickwright workbench requests

This is the durable backlog for the retro machines, circuit examples, and workbench UI. Keep each item here when work moves between agents, repositories, or builds. Mark an item verified with the commit and the exact test or observed workflow. A working boot, a rendered widget, and a passing program each provide different evidence.

## Current priorities

1. Make the machine paths predictable. Run current Code from the green flag, keep guest input and output in Controller, and keep debugger inspection independent of the selected right-pane view.
2. Organize Machines by CPU or device. Place 8086 ELKS, DOS programs, and video and input presets together. Place TOPBENCH and 386 boot media together under 80386. Apply the same ordering to saved images, lessons, downloads, and compatible circuit examples. Preserve search and the single-machine filter.
3. Fix PicoBB LittleFS and its console. Check mounting an initialized filesystem and actually saving, loading, and executing a BASIC program. Test raw terminal control sequences, keyboard input, and fullscreen with the real guest.
4. Keep filling the functional circuit coverage gap. Use the CLI and report startup and lesson behavior independently.
5. Unify editor overflow menus around the Robots design after the machine work. Include CAD and FPGA capabilities in the local test build.

## Verified in the current integration

- The Controller browser suite ran Linux commands, tested help and fullscreen, switched panes with the same guest, and checked CP/M Sieve source and output plus the green flag’s Tcl precedence. The Code suite compiled edited RISC-V C with hosted GCC. The direct x86 debugger route ran 8086, 80286, and 80386 BIOSes and showed video in Controller. These cover the integration through `d9c4794`.
- The latest library and hardware sweeps cover 25 launch paths, both Spectrum profiles with authored ROMs, the G-Pascal ROM, KIM-1, CP1, Microtronic, and the separate BBC BASIC TMS9918A lesson. They give a baseline for rerunning acceptance after the menu and PicoBB work. Firmware coverage remains limited to the specific images and interactions exercised.
